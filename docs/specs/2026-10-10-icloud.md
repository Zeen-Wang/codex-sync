# iCloud shared-folder transport

Use an explicitly selected, existing shared folder; never infer sharing from Family
Sharing membership or create a missing root. Each Apple account configures its own
local path. The provider is sessions-only and retains local authentication, config,
keys and databases. Storage remains age encrypted with the existing key derivation.

Unlike object stores, iCloud has no distributed compare-and-swap or reliable lock.
Store append-only, content-addressed revision records (key, parent, timestamp,
ciphertext). Validate hashes and complete ancestry before selecting a single head.
Multiple heads fail closed; never pick a winner by clock. Local atomic publication
prevents partial reads, but cannot ensure cloud delivery or cross-Mac exclusion.
Conditional uploads compare the locally visible head to the last pulled revision;
offline races remain possible and are detected after replication. Retain every
revision for recovery. Never infer deletion from absence, and reject all remote
deletes, even forced ones. No automatic pruning or background scheduling.

An incomplete but internally consistent local replica cannot be detected. Operators
must use one Mac at a time, wait for Finder synchronization, pull before editing,
and keep independent backups. Unit tests simulate reordered delivery, missing
parents, forks, and two separate local identities; real two-Apple-ID validation
remains a manual acceptance check.
